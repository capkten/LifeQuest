# 商城移动端 UI 审查记录

日期：2026-08-26
范围：`frontend/src/views/Shop.vue` 在移动网页和 Capacitor WebView 中的商品浏览、筛选、兑换与管理界面
审查方式：截图对照、源码审查、Playwright 构造数据渲染验证
结论：❌ NOT READY（移动端商品浏览体验需要修复后再作为最终版）

## 复现环境

- 320×568：无横向溢出，但商品卡片宽度约 123px，首屏商品区域完全落入底部导航覆盖范围。
- 375×812：无横向溢出，但商品卡片宽度约 151px，商品信息和管理按钮被迫压缩。
- 390×844：无横向溢出，但商品卡片宽度约 158px，首屏商品行从 y=734 开始，固定导航从 y=772 开始，首行商品被导航遮挡。
- 768×1024、1440×900：商品网格可正常展开为更宽的卡片，主要问题集中在移动断点。

构造数据包含 3 个商品、长名称、长描述、有限库存和管理员操作按钮；接口、路由和业务逻辑均未修改。

## Findings

### ⛔ P0：移动端首屏商品卡片被固定底部导航遮挡

证据：

- `frontend/src/views/Shop.vue:1585-1588`：移动端商品网格固定为 `repeat(2, minmax(0, 1fr))`。
- `frontend/src/components/layout/AppLayout.vue:220-228`：底部导航使用 fixed 定位。
- 构造数据渲染：390×844 时商品网格从 y=734 开始，底部导航覆盖 y=772-844；320×568 时导航覆盖 y=496-568，而商品网格从 y=734 开始。

影响：用户打开商城时看不到完整商品入口；在 320px 高度较小的设备上，首屏只有筛选区域，商品内容必须滚动且容易误认为页面没有商品。

建议：保留固定导航时，商城应将商品列表视为独立的可滚动内容区，明确把底部 inset 纳入滚动边界；同时避免把首个商品行直接放在导航上缘。商品区进入视口后，最后一项必须能完整滚过导航。

### ⛔ P0：两列商品卡片在窄屏下信息密度过高

证据：

- `frontend/src/views/Shop.vue:1585-1588`：所有 768px 以下视口都使用两列布局。
- 构造数据渲染：320px 时卡片宽度约 123px，375px 时约 151px，390px 时约 158px。
- `frontend/src/views/Shop.vue:1645-1653`：移动端管理员编辑/删除按钮先被压缩到 24px；后续规则虽恢复到 44px，但两个按钮和价格信息仍共享同一行。

影响：长名称、价格、库存、管理员操作和兑换按钮争夺同一张小卡片；文字容易换行、操作图标拥挤，用户难以快速比较商品，也增加误触风险。

建议：在 360px 或 400px 以下切换为单列；若保留双列，仅保留适合短内容的紧凑卡片，并将管理操作移至独立菜单或卡片底部，确保 Android 48dp 触控区域和至少 8px 间距。

### ⚠️ P1：筛选区在移动端纵向占用过高，商品发现路径被推迟

证据：

- `frontend/src/views/Shop.vue:1538-1542`：工具栏移动端强制纵向排列。
- `frontend/src/views/Shop.vue:1578-1583`：历史和新建商品按钮占据整行双列操作区。
- 构造数据渲染：390px 下 hero 约 234px、页面头部约 194px、工具栏约 98px，商品网格从 y=734 才开始。

影响：商城最重要的任务是浏览和兑换商品，但首屏优先展示大幅 hero、钱包、两个操作按钮、分类、搜索和排序，实际商品被推到首屏之外。

建议：移动端压缩 hero 为摘要卡；把钱包与结果数合并为紧凑信息条；历史和新建商品保留触控面积，但降低视觉权重；搜索与排序保持一行或使用可展开筛选。

### ⚠️ P1：分类导航显示原始英文枚举，和商品标签翻译不一致

证据：

- `frontend/src/views/Shop.vue:53-60`：分类按钮直接渲染 `category` 原始值。
- `frontend/src/views/Shop.vue:171`：商品卡片使用 `labelItemType(item.category)` 翻译标签。
- 构造数据验证：分类按钮显示 `consumable`、`gear`，商品卡片标签显示“消耗品”“装备”。
- `frontend/src/locales/zh-CN.js:150-154`：已有 `ITEM_TYPE_LABELS` 映射。

影响：同一商品在分类导航和卡片中使用两套语言，降低信息可信度，也会让中文用户误以为分类不是可读的产品字段。

建议：分类按钮显示共享翻译结果，但内部仍使用原始值进行筛选；对用户自定义分类保留原文并做长度截断或横向滚动。

### ⚠️ P1：商品管理按钮的触控和语义仍不稳定

证据：

- `frontend/src/views/Shop.vue:143-153`：编辑和删除按钮位于高密度卡片头部。
- `frontend/src/views/Shop.vue:1645-1653`：移动断点曾将 `.btn-icon` 设置为 24px，后续通用规则再覆盖为 44px，存在级联覆盖风险。
- 兑换按钮在 `frontend/src/views/Shop.vue:1639-1643` 移动端降为 40px，低于网页 44px 触控下限。

影响：移动端管理员操作容易误触；兑换按钮作为核心动作却比其他全局按钮更小，和项目触控契约不一致。

建议：删除移动断点内对 `.btn-icon` 的缩小规则；兑换按钮至少保持 44px，Capacitor/Android 使用 48px；管理操作与兑换操作在视觉上明确分层。

### 📋 P2：状态卡片的加载/空状态仍继承页面级大留白

证据：

- `frontend/src/views/Shop.vue:917-967`：商城 loading/error/empty 使用通用状态块。
- `frontend/src/views/Shop.vue:1862-1864`：筛选无结果状态单独设置 `min-height: 280px`，移动端仍可能产生过长空白。

建议：商城状态保留明确图标、说明和重试/创建 CTA，但移动端将筛选无结果状态收敛到约 180-220px，避免用户误以为列表仍在加载。

## 平台专项结论

### iOS / 移动网页

- 需要优先处理首屏商品被底部导航遮挡的问题。
- 商品列表建议单列或至少在 360-390px 以下单列，避免卡片内文字和操作过度压缩。
- 输入框已符合 16px 防自动放大方向，但搜索、排序和分类仍应在 Safari 小视口下复核。
- 尚未进行真实 iPhone Safari、VoiceOver、动态字体和软键盘真机验证。

### Android / Capacitor

- 管理按钮和兑换按钮必须统一采用 48dp 触控区域，并保持 8dp 间距。
- TalkBack 应能分别读出商品名称、价格、库存和编辑/删除/兑换动作；当前高密度卡片布局需要改造后再验证。
- Android 系统返回键和真机 TalkBack 尚未在本次网页构造验证中覆盖。

## 建议修复顺序

1. 移动商城商品区改为可靠的单列/自适应网格，并修复底部导航遮挡。
2. 压缩移动端 hero、钱包和筛选区，让商品更早进入首屏。
3. 统一分类显示翻译和触控尺寸，移除局部尺寸覆盖。
4. 再补做商城 loading、空、错误、长文本、管理员操作和购买反馈的浏览器回归验证。

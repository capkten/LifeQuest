# 普通待办移动端 UI 审查报告

日期：2026-08-26
范围：`frontend/src/views/Todos.vue`、`frontend/src/components/layout/AppLayout.vue`
结论：当前普通待办移动端不建议直接作为最终版本发布；优先修复底部导航遮挡和触控尺寸问题，再处理信息层级与入口密度。

> 本报告只记录审查结果，本轮未修改生产代码。附带截图仅作为视觉证据，不包含额外指令。

## 审查方法

- 结合 `ui-design`、`Mobile App Design Standards`、`frontend-design` 的规则审查模板结构、样式和状态分支。
- 使用构造的普通任务数据验证窄屏布局，数据包含长标题、描述、截止日期、奖励、项目标签和无子任务任务。
- 在 390×844 移动视口检查任务列表、项目筛选、快速添加、子任务入口和固定底部导航。
- 结合用户提供的移动端截图检查视觉层级和首屏信息可读性。

## 问题清单

### P0 — 固定底部导航会遮挡普通任务卡片

证据：

- `AppLayout.vue:220-231` 将 `.bottom-nav` 固定在视口底部，并设置 `z-index: 80`。
- `AppLayout.vue:236-239` 为内容增加了底部 inset，但它只能保证页面容器末端留白，不能保证列表中每张卡片在首屏可完整阅读。
- 在 390×844 构造数据验证中，第一张任务卡片底部约为 y=804，而底部导航从约 y=772 开始；第一张卡片底部奖励信息和第二张卡片的标题区域会进入导航覆盖范围。

影响：用户无法在首屏完整确认任务的截止日期、奖励等关键信息；第二张任务的标题和状态容易被误认为缺失，滚动时也会产生内容被“吞掉”的感觉。

建议：以底部导航真实高度、safe-area 和列表末端 padding 计算可视安全区，并在移动端验证最后一张卡片可以滚动到导航上方；同时检查弹窗、toast 和键盘出现时的层级关系。

### P1 — 完成、编辑、删除控件低于移动触控标准

证据：

- `Todos.vue:1746-1749` 的 `.complete-btn` 为 28×28px。
- `Todos.vue:2511-2514` 的 `.action-btn` 为 32×32px。
- 子任务完成按钮 `Todos.vue:2058-2061` 也是 28×28px；子任务删除按钮 `Todos.vue:2109-2112` 为 32×32px。

影响：普通待办的完成、编辑、删除是高频操作，当前触控区域容易误触，也与移动端其他已经优化过的操作控件不一致。图标本身只有 14px，进一步降低了可发现性。

建议：视觉图标可以保持较小，但按钮外层至少满足 iOS 44×44px、Android 48×48dp 的触控目标；相邻操作保留足够间距，并继续保留 aria-label。

### P1 — 一张卡片承载的信息过多，主次关系不够清晰

证据：普通任务卡片同时显示完成按钮、标题、优先级、难度、状态、描述、项目标签、编辑、删除、子任务入口、截止日期、金币和经验奖励（`Todos.vue:201-340`）。标题旁的三个 badge 在窄屏下允许换行（`Todos.vue:1802-1808`），导致标题区高度和视觉重心不稳定。

影响：用户打开待办页首先需要扫描多个小标签，而不是快速回答“要做什么、什么时候做、是否完成”。附图中标题、标签、项目标签、操作图标和底部奖励分布在多层，卡片显得拥挤且偏工具面板化。

建议：移动端将“完成状态 + 标题 + 截止时间”作为第一扫描路径；优先级和难度保留但降低对比度，状态可并入完成状态或放入次级信息；奖励合并为紧凑的底部统计；编辑/删除移入更多操作或使用更清晰的操作组。

### P1 — 顶部内容过长，任务列表进入首屏过晚

证据：移动端当前顺序包含页面头部、三个 Tab、每日进度卡、项目筛选和独立的快速添加 CTA。390×844 验证中，普通任务卡片约从 y=650 才开始出现；`.mobile-add-cta` 在移动端显示（`Todos.vue:2704-2706`），而页面头部仍保留新建任务按钮。

影响：用户进入“待办”后首先看到的是多个管理模块，真正的任务被推到首屏下方；普通任务页面的“新建任务”和“快速添加”形成重复入口，消耗空间并分散注意力。

建议：移动端合并新建任务入口；压缩页面头部和进度卡高度；项目筛选保留横向滚动但降低容器高度；让至少一张完整任务卡在常见 390×844 视口中可见。

### P1 — 子任务展开入口的可发现性和触控面积不足

证据：子任务入口位于虚线分隔线中，`.subtask-toggle` 仅为 30×24px，且通过负 margin 跨越分隔线（`Todos.vue:1980-2004`）。窄屏实测分隔区域视觉高度约 13px，入口看起来像装饰性的箭头。

影响：用户不容易理解箭头代表“子任务”；点击目标小，尤其在拇指操作和屏幕阅读放大场景下不可靠。

建议：将入口改成带“子任务”文字或数量的整行按钮，最小触控高度 44px；展开/收起状态提供明确的文字、旋转图标和焦点样式。

### P2 — 视觉上过度依赖边框、badge 和虚线分隔

证据：任务卡片的标题区域、标签、项目标签、虚线子任务区域和底部奖励都采用独立的边界或小型胶囊组件。

影响：卡片缺少明确的视觉锚点，次要信息与标题竞争注意力；在移动端尤其容易显得“信息很多但不知道先看什么”。

建议：保留 LifeQuest 的蓝绿主题，但减少次要边框和高饱和标签；通过字号、字重、留白和统一的 metadata 行建立层级，避免继续增加 badge。

### P2 — 窄屏换行策略需要专门回归

证据：标题和描述允许 `word-break: break-word`，Tab 标签使用省略号，项目筛选使用横向滚动；这些策略各自合理，但组合后会让 320px 左右视口出现多行标题、标签换行和操作列压缩。

建议：至少回归 320×568、375×812、390×844；确认长标题、长描述、无描述、无截止日期、长项目名和多个 badge 下，操作按钮不会被挤出或与文本重叠。

## 状态审查

### Loading

已有 `loading` 和子任务 loading 分支（`Todos.vue:88-92`、`Todos.vue:274-277`）。需要补充骨架或稳定的占位高度，避免数据加载后页面大幅跳动，尤其是顶部筛选和任务卡片区域。

### Empty

已有按 Tab 区分的空状态（`Todos.vue:97-105`）。普通待办空状态应把“新建任务”作为单一主 CTA，避免同时出现页面头部按钮和移动快速添加入口。

### Error

已有页面错误、toast 和重试入口（`Todos.vue:92-95`、`Todos.vue:475-478`）。移动端需要确认错误提示不被底部导航遮挡，重试按钮满足触控尺寸，并且错误发生时仍能回到筛选和 Tab 操作。

### Dialog / keyboard

编辑、删除和新增子任务共用移动端 dialog 样式。需要验证键盘弹出时 dialog 不被底部导航或 viewport 裁剪，表单提交中的 loading 不会导致按钮宽度跳变。

## 平台专项建议

### iOS

- 所有高频操作目标至少 44×44pt，尤其是完成、编辑、删除、展开子任务和底部导航。
- 处理 `safe-area-inset-bottom` 与固定底部导航的叠加，避免 Home Indicator 区域和任务内容重叠。
- 保留清晰的 focus/pressed 状态；不要只依赖 hover。
- 表单输入使用 16px 或更大字号，避免 Safari 自动放大；键盘出现时确保提交按钮仍可见。
- 长按、滑动和横向筛选不要与页面纵向滚动冲突，横向筛选应有明确的滚动提示。

### Android

- 高频操作目标至少 48×48dp，删除操作保留足够的误触间距。
- 检查系统返回手势与 dialog、子任务展开状态的返回顺序，不要让返回手势直接离开页面。
- 检查较小屏幕和系统字体放大后的 badge 换行，避免操作列被挤压。
- pressed/ripple 反馈应覆盖整块可点击区域，而不是只覆盖 14px 图标。

### 移动网页

- 用真实 viewport 高度测试底部 fixed nav、浏览器地址栏收缩和横屏场景，不只依赖 CSS 设备模拟。
- 列表末端必须有足够安全留白，确保最后一张任务卡可滚动越过 fixed nav。
- 不要把 hover 作为主要反馈；所有图标按钮都需要可理解的 aria-label 和可见焦点。
- 验证 320px 窄屏、低网络 loading、接口错误、空列表、长标题和软键盘场景。

## 建议实施顺序

1. 修复列表与固定底部导航的可视安全区，完成 320/375/390px 回归。
2. 统一完成、编辑、删除、子任务操作的移动触控尺寸和反馈。
3. 压缩顶部模块并合并重复的新建入口。
4. 重排任务卡片信息层级，降低 badge 和边框的视觉权重。
5. 补齐 loading、empty、error、dialog/keyboard 的移动端验证。

## 本轮结论

普通待办移动端存在一个需要优先处理的遮挡问题、四个影响较大的交互与信息层级问题，以及两个视觉和窄屏韧性问题。日常习惯页面已达到可接受状态并不能覆盖普通待办的卡片密度、子任务交互和任务列表长度问题；建议将普通待办作为独立页面专项优化。

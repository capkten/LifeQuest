# LifeQuest 当前问题审查记录

日期：2026-08-18
分支：`codex/cultivation-progression-ui`
范围：通用业务流程、前后端接口、修仙模块内容与交互

## 审查状态

本文件只记录审查发现，不代表问题已经修复。上一轮通用模块问题与本轮修仙模块问题统一收录，后续修复后应保留原问题、修复提交和验证结果。

## 通用模块问题

### P1

- 待办习惯完成状态契约错误：`HabitResponse` 缺少 `completed_today`，前端又使用 `is_active` 判断完成，导致完成状态、进度和重复奖励反馈不正确。
- 金币明细接口不匹配：前端发送 `page`、`income/expense` 并读取 `data`，后端接收 `skip`、`earn/spend` 并返回 `transactions`。
- 财务流水分页不匹配：前端发送 `page`，后端只接收 `skip`，加载更多会重复第一页。
- 签到响应缺少奖励字段，成功提示可能显示获得 0 金币和 0 经验。
- 项目详情页创建、完成、保存操作缺少提交锁；阶段删除没有确认且会影响阶段下任务归属。

### P2

- Todos、Shop、Backpack 等页面使用全局操作锁，其他仍可点击的按钮会直接静默 `return`。
- 条件不满足的按钮大量使用原生 `disabled`，用户点击没有反馈或解释。
- Finance、Calendar、Notes、Home、Profile 等页面把请求失败降级成空数据或只写控制台。
- 笔记编辑加载失败后仍显示空编辑器，没有稳定错误态和重试入口。
- 笔记工作区创建、重命名、移动缺少提交状态，查看器切换缺少请求序号保护。
- Header 用户菜单内层路由点击会冒泡，跳转后菜单可能重新打开。
- Notes、Finance、Stats 等筛选或搜索请求存在旧响应覆盖新选择的竞态。

## 修仙模块问题

### P1

- 渡劫丹没有资源闭环：`pill_count` 只影响成功率，后端没有库存、余额校验或扣除逻辑，客户端可以直接提交 15 颗获得概率加成。
- 渡劫前置条件未实现：当前服务主要检查最终小境界和冷却，设计中要求的目标、习惯连续天数、重要历练、宗门贡献等条件没有真正参与判定。
- 宗门试炼不是实际内容：`complete_sect_trial` 只把 `trial_confirmed` 改为 `True`，没有任务、条件、奖励或失败状态，用户可以直接完成入门试炼。
- 修仙资源不完整：奖励结算只增加修为和灵石，功德、宗门贡献、资质点、心境、修炼效率没有形成增长路径；页面展示的这些资源会长期保持初始值。
- 功法效果没有接入结算：学习和装备功法只记录关系，`cultivation_efficiency` 不会按功法变化，宗门核心传承也没有实际效果。
- 功法格子购买缺少数据库唯一约束或行锁，并发请求可能得到相同 `slot_index`，重复扣除灵石并创建重复格子。

### P2

- 功法格子规则与内容不一致：高阶格子境界要求只定义到合体，后续格子会重复使用合体要求；价格递增使用 2 倍而设计记录为 2.4 倍。
- 功法类型与格子类型没有后端校验，任意已学习功法都可能被配置到不匹配的格子类型。
- 功法类型文案不一致：同一个 `body` 类型在功法库显示“炼体”，在格子显示“身法”；当前目录只有 3 部功法，辅修格子没有对应内容。
- NPC 人口槽位只校验非负数，没有上限；重复遇见同一 NPC 会无限新增事件，容易产生无意义的关系记录。
- 宗门任务偏好、核心传承和宗门贡献目前只有展示字段，没有参与任务奖励、功法或成长分支。
- 隐藏宗门始终从列表中过滤，当前没有现身条件、解锁流程或可达路径。
- 地图目前只有 9 个节点，且第 2 至第 9 个节点统一要求筑基；达到筑基后会同时开放大量节点，和设计中的分区推进不一致。
- 所有飞升后境界、仙界资源和仙官系统尚未落地，`ascended` 更接近终点标记而不是完整的飞升后循环。
- 修仙后端错误码多数没有前端中文映射，例如境界不足、灵石不足和宗门条件失败最终只显示通用“请求冲突”。
- 渡劫准备度算法过于粗糙：最近 7 天只要有一次习惯完成即可获得较高分；任务质量主要按难度平均，没有按时、延期或目标契合度计算。

## 验证和风险

- 已知构建和现有后端、前端回归测试可以通过，但这些测试没有覆盖真实浏览器条件点击、并发格子购买、渡劫丹库存扣除和修仙数值长期模拟。
- 当前环境缺少可直接启动后端所需的 SQLAlchemy，修仙动态页面没有可用的已认证浏览器会话时，应把结论标记为代码与测试审查，不冒充完整手测。

## 建议修复顺序

1. 先封堵渡劫丹免费加成、格子并发重复扣款和待办奖励接口契约问题。
2. 明确修仙资源和数值规则的唯一来源，补齐功德、资质、心境、贡献及功法效果的结算路径。
3. 把宗门试炼、隐藏宗门和地图节点从展示数据升级为真实状态机，并补充前后端交互反馈。
4. 增加并发、长期数值模拟和已认证浏览器流程测试。

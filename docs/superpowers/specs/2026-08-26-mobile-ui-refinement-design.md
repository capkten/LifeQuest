# LifeQuest 移动端 UI 优化设计

日期：2026-08-26

## 目标

在保持现有业务流程、API 调用和页面功能不变的前提下，优先改善移动端的可用性：窄屏不遮挡、触控目标稳定、弹窗可操作、加载/空/错误状态可理解。

## 范围

- 移动网页和 Capacitor WebView 共享的应用壳层。
- 首页、笔记、统计、财务和笔记编辑器的移动布局与状态展示。
- 已存在的弹窗、底部导航、顶部菜单和交互卡片。
- 不重做品牌色、字体方向，不修改后端，不改变业务数据契约。

## 设计决策

### 1. 移动应用壳层

保留 5 项底部主导航，继续使用图标 + 文字标签。底部导航保持固定，但内容滚动区域以导航高度和 `safe-area-inset-bottom` 计算有效底部空间，保证首屏、中段和最后一项均可滚过导航。移动侧栏继续作为模态抽屉，打开后关闭遮罩并在路由变化时收起。

### 2. 触控和平台适配

- 移动网页交互区域最低 44px。
- Capacitor/Android 交互区域按 48px 设计，至少保持 8px 间距。
- 关闭、返回、菜单和列表操作按钮使用统一的可触控尺寸；图标可以小于触控区域，但不能缩小实际 hit area。
- 保留现有 CSS token，新增平台差异只通过壳层或组件级 token 表达。

### 3. 视口与键盘

对全屏壳层、笔记编辑器、弹窗和日历等区域采用 `100vh` 兼容回退 + `100dvh` 优先策略。编辑器和弹窗内容允许滚动，软键盘展开时保存/取消操作仍可见。

### 4. 弹窗和语义交互

不改变弹窗触发方式和业务动作，但统一以下行为：打开后焦点进入弹窗，Tab 在弹窗内部循环，Esc/取消按现有规则关闭，关闭后焦点回到触发控件，标题通过 `aria-labelledby` 关联。Notes 搜索结果和笔记本入口优先使用真实按钮或链接；无法替换时补齐 Enter/Space 和可见焦点。

### 5. 状态设计

- loading：保留容器最小高度，避免内容加载后跳动。
- empty：保留当前产品语气，补充进入下一步的明确 CTA，尤其是首页今日任务和笔记列表。
- error：错误信息与重试按钮同处可见区域，使用 `role="alert"` 或合适的 live region。
- pending/disabled：按钮尺寸稳定，保留进行中的文字或 spinner，并让不可用原因可理解。

### 6. 视觉收敛

保留蓝绿色 LifeQuest 视觉系统。减少移动端不必要的卡片高度和重复留白；标题、正文、标签和导航使用稳定的移动字号下限。局部样式只在现有组件范围内调整，不引入新的视觉风格或大规模组件重构。

## 验证方案

- 先为移动壳层安全区、Notes 语义交互和状态布局添加可重复的静态/浏览器回归检查，并确认测试先失败。
- 使用构造 API 数据验证 375×812、390×844、768×1024 三种视口。
- 覆盖 populated、loading、empty、error、dialog open、dialog close 和软键盘近似窄高视口。
- 检查横向溢出、固定导航遮挡、弹窗操作区可见性、长文本换行和控制尺寸。
- 运行前端构建及现有回归测试；不声称已完成 iOS VoiceOver、Android TalkBack 和系统返回键真机验证。

## 不在本次范围

- 后端接口、数据模型、业务规则和权限。
- 原生 Android 返回键的最终实现；本次先保留验证结论，若代码证据要求处理，将单独加入实现计划。
- 完整 PWA 离线缓存、原生 Haptics、原生字体和深色模式重设计。

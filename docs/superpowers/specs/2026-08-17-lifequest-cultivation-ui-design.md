# LifeQuest 修仙 UI 设计规格

> 状态：设计稿，待用户审阅后进入实现计划
> 日期：2026-08-17
> 关联规格：[lifequest-cultivation-world-design.md](./2026-08-17-lifequest-cultivation-world-design.md)
> 技术栈：Vue 3、Vue Router、Element Plus、现有 CSS 变量体系

## 1. 设计目标

在现有 LifeQuest 生产力工作台上增加修仙成长层。用户首先看到和操作的仍然是现实待办、习惯、项目和笔记；修为、宗门、功法、NPC 和仙官作为任务完成后的成长反馈与长期目标出现。

本设计不把产品改造成全屏暗黑游戏界面，不使用大型装饰性地图或营销式首页。核心页面必须支持快速扫描、重复操作和移动端单手完成。

## 2. 当前 UI 基线

现有 UI 的主要约束来自以下文件：

- `frontend/src/App.vue`：全局字体、颜色变量、间距、圆角、阴影和响应式基线。
- `frontend/src/components/layout/AppLayout.vue`：桌面侧栏、移动端底部导航和内容容器。
- `frontend/src/components/layout/Sidebar.vue`：PLAN、REWARDS、INSIGHTS 导航分组。
- `frontend/src/components/layout/Header.vue`：页面标题、侧栏按钮和用户菜单。
- `frontend/src/views/Home.vue`：欢迎区、今日任务、快速行动、最近任务和目标。
- `frontend/src/views/Todos.vue`：习惯、任务、目标标签页和任务卡片。
- `frontend/src/styles/stitch-overrides.css`：Element Plus 和现有工作台样式覆盖。

当前视觉基线：

- 浅色蓝白背景，主色为 `#0EA5E9`。
- 主文字为 `#16324F`，次要文字为 `#5B7185`。
- `DM Sans` 用于正文，`Space Grotesk` 用于标题和数字。
- 固定左侧栏，移动端使用底部导航。
- 14 至 18px 圆角、轻阴影、细边框和中等密度卡片。
- 现有项目使用 Element Plus，并有大量内联 SVG 图标。

UI Pro Max 推荐的微交互、移动优先、明确加载状态和可访问性规则纳入本设计；推荐的 `Caveat / Quicksand` 不采用，以保持与现有工作台一致。

## 3. 视觉系统

### 3.1 颜色

继续使用现有全局变量，不重命名已有变量。修仙功能增加以下语义色：

| 语义 | 建议颜色 | 用途 |
| --- | --- | --- |
| 修为 | `#2563EB` | 修为进度、境界节点和主要成长反馈 |
| 灵石 | `#B45309` | 灵石余额、商城价格和经济变化 |
| 功德 | `#047857` | 功德、善缘和 NPC 帮助 |
| 仙元 | `#4F46E5` | 飞升后仙界进度，限制在局部组件使用 |
| 渡劫风险 | `#B91C1C` | 失败损失、低成功率和危险状态 |
| 成功 | `#16A34A` | 完成、突破成功和正向反馈 |

颜色不能是唯一状态指示。所有状态同时使用文字、图标、边框或进度标识。

不使用大面积渐变、发光边框、独立装饰球、星空背景或高饱和紫色主题。渐变只保留现有进度条中用于表达连续进度的用途。

### 3.2 字体与尺寸

- 正文继续使用 `DM Sans`，最小正文尺寸 16px。
- 标题继续使用 `Space Grotesk`，页面标题 20 至 24px，区块标题 16 至 18px。
- 正文行高 1.5 至 1.75，单行长度控制在 65 至 75 个字符以内。
- 触控目标不小于 44px，图标按钮之间至少保留 8px 间距。
- 现有 `--surface-radius`、`--surface-padding` 和 `--page-gap` 作为修仙页面默认值。

### 3.3 图标和动效

- 优先使用项目已经启用的 Element Plus 图标体系；不新增第二套图标风格。
- 图标按钮必须有 `aria-label`，陌生图标提供 tooltip。
- 完成反馈、进度变化和状态切换使用 150 至 300ms 的颜色、透明度或宽度动画。
- 不使用会改变布局尺寸的 hover 缩放。
- 支持 `prefers-reduced-motion`，减少动画时不影响信息和操作。

## 4. 信息架构

### 4.1 桌面导航

在现有导航中增加 `CULTIVATION` 分组：

```text
PLAN
  首页
  待办
  项目
  日历
  笔记

CULTIVATION
  修炼总览
  世界地图
  宗门
  功法
  NPC 关系
  渡劫

REWARDS
  商城
  背包

INSIGHTS
  记账
  统计
  个人
```

渡劫入口在用户满足前置条件前显示为锁定状态；仙界和仙官入口在飞升前不显示在主导航中，避免导航堆积未解锁功能。

### 4.2 移动导航

移动端底部导航为：

```text
首页 · 待办 · 修炼 · 商城 · 个人
```

修炼页内部使用顶部或页面内标签切换世界地图、宗门、功法和 NPC。仙界解锁后，修炼页内部增加仙界和仙官入口，不扩大底部导航数量。

### 4.3 建议路由

```text
/cultivation
/world
/sects
/techniques
/npcs
/tribulations
/immortal
/officials
/officials/quests
```

实际路由命名应遵循现有 `router/index.js` 的命名风格；未解锁路由由页面守卫或页面状态处理，不通过前端硬编码隐藏后端权限。

## 5. 核心页面设计

### 5.1 首页与待办的修仙增强

首页继续以现实行动为主，不替换现有欢迎区、今日任务和快速行动。

欢迎区增加一个紧凑的修炼状态行：

```text
炼气三层 · 128 / 180 修为 · 今日 +45 修为
```

现有 `EXP TO LEVEL` 文案在修仙资料加载成功后替换为当前境界和修为；旧接口或资料尚未迁移时继续显示旧等级，避免空白。

今日任务区的每个任务增加：

- 任务星级；
- 预计修为；
- 预计灵石；
- 习惯连续天数；
- 延期后的完成质量提示。

完成任务后的反馈顺序：

```text
任务完成
  -> 卡片状态变为已完成
  -> 行内显示 +修为、+灵石
  -> 更新境界进度
  -> 写入修炼日志
```

不使用全屏奖励弹窗打断连续完成任务。网络请求超过 300ms 显示按钮 loading；失败使用 `role="alert"` 的错误提示和重试操作。

### 5.2 修炼总览

桌面端使用 7/5 两列布局，移动端单列堆叠。

主区内容：

- 当前大境界和小境界；
- 当前修为与阶段阈值；
- 下一小境界或突破前置；
- 今日修为、近 7 日修为和连续习惯；
- 最近奖励流水。

侧区内容：

- 心境；
- 资质点；
- 灵石、功德和宗门贡献；
- 当前功法方案；
- 下一个可解锁节点。

顶部使用紧凑资源条，不使用四个巨大数字卡片占满首屏。主要行动按钮只有一个，例如“查看突破试炼”或“前往今日历练”。

### 5.3 世界地图

地图使用可扫描节点布局，不使用大面积装饰插画。

节点状态：

- 当前节点：主色边框和文字标识；
- 已完成：低对比度完成图标；
- 可进入：主色行动按钮；
- 锁定：锁图标、解锁条件和不可用状态；
- 宗门区域：节点旁显示宗门数量和当前境界要求；
- 突破地点：使用独立的渡劫风险色，但不使用红色填满整个节点。

桌面端地图左侧为节点图，右侧为选中节点详情。移动端先显示节点列表，点击后展开详情，避免横向拖拽影响任务操作。

### 5.4 宗门选择

宗门选择页面向比较和决策，不采用营销式大卡片。

筛选项：

- 星级；
- 普通、特殊、隐藏类型；
- 任务偏好；
- 核心传承标签；
- 入门境界。

每个宗门条目显示：

- 宗门名称和类型；
- 核心传承；
- 功法效果；
- 三名固定核心 NPC；
- 适合的现实任务标签；
- 试炼条件；
- 加入、比较和查看详情操作。

特殊宗门用左侧色条和传承图标区分；隐藏宗门只有触发后才进入列表。

### 5.5 功法与格子

页面由三部分组成：

1. 当前功法方案：主修、辅修、心法和身法槽位；
2. 格子区域：稳定尺寸的空槽、已装备功法和占用格子数；
3. 功法库：筛选、境界限制、冲突标签、学习和装备操作。

格子使用固定宽度和宽高比，功法名称过长时换行，不允许内容变化导致布局跳动。冲突状态同时显示冲突图标、文字和边框；不能只用颜色表达。

购买格子使用独立确认区，显示：

```text
第 4 格
需要境界：筑基
价格：800 灵石
购买后剩余：1,240 灵石
```

### 5.6 渡劫页面

渡劫页以风险透明为核心，桌面端左右两列，移动端按风险到操作顺序堆叠。

左侧：

- 当前境界和目标境界；
- 当前小境界修为；
- 失败损失预览；
- 下一次可尝试时间。

右侧：

- 基础成功率；
- 心境贡献；
- 习惯贡献；
- 任务质量贡献；
- 渡劫试炼贡献；
- 功法和宗门契合贡献；
- 渡劫丹数量；
- 最终成功率。

示例：

```text
基础成功率       40%
渡劫准备度       72 分
准备度加成       +4%
渡劫丹           2 颗，+10%
最终成功率       54%
失败损失         当前小境界修为的 20%
```

主按钮使用明确文本“开始渡劫”。提交期间禁用并显示 loading。成功、失败和冷却状态保留完整结果，不允许重复提交。

### 5.7 NPC 关系

NPC 页分为：

- 固定核心 NPC；
- 最近遇见；
- 当前行程；
- 关系等级；
- 最近事件；
- 可触发任务。

每日修为更新使用时间线展示：

```text
今日：韩越闭关修炼，修为 +18
本周：白芷晋升内门弟子
```

已建立关系的 NPC 显示完整历史；普通未遇见弟子只显示人口统计，不制造空白头像和无内容列表。

### 5.8 仙界与仙官

飞升后增加三个入口：

- 仙界地图；
- 仙籍官职；
- 官署大厅。

仙籍官职页显示：

- 当前仙界境界；
- 仙籍和官职品阶；
- 仙功；
- 官职表现；
- 当前官署；
- 晋升条件；
- 调任和监察状态。

官署大厅显示司主、掌事仙官、传法仙官、监察仙官、同僚和竞争者。仙官任务继续复用现实待办，使用现有任务列表样式，不另造一套游戏任务卡片。

## 6. 组件边界

新增组件建议保持小而专一：

```text
components/cultivation/CultivationStatusBar.vue
components/cultivation/RealmProgress.vue
components/cultivation/ResourceSummary.vue
components/cultivation/RewardToast.vue
components/cultivation/TribulationProbability.vue
components/cultivation/TechniqueSlotGrid.vue
components/cultivation/MapNode.vue
components/cultivation/NpcTimeline.vue
components/officials/OfficialRankBadge.vue
components/officials/OfficialQuestList.vue
components/officials/OfficialPerformance.vue
```

组件只负责展示和用户交互，资源结算、概率计算、任务奖励和权限判断必须通过 services/store/API 完成。

## 7. 状态与反馈

每个新页面至少定义以下状态：

- 初始加载：骨架屏或局部 spinner，预留稳定尺寸；
- 空状态：说明下一步动作，不使用装饰性空白；
- 锁定状态：显示解锁条件和前往条件来源的入口；
- 错误状态：近距离显示错误和重试按钮，并使用 `role="alert"`；
- 操作中：禁用当前按钮，显示 loading，避免重复请求；
- 成功状态：行内结果、toast 或时间线记录；
- 失败状态：展示损失、保留内容和恢复路径。

## 8. 响应式和可访问性

必须验证以下视口：`375px`、`768px`、`1024px`、`1440px`。

- 375px：单列、底部导航、关键概率和主按钮优先；
- 768px：折叠侧栏，两列内容；
- 1024px：完整侧栏，两列工作台；
- 1440px：内容最大宽度约 1200px，允许三列辅助信息。

通用要求：

- 使用 `nav`、`main`、`section`、`button` 等语义元素；
- 动态状态同步 `aria-expanded`、`aria-pressed` 和 `aria-valuenow`；
- 所有可点击元素有 pointer、hover 和 focus-visible 状态；
- 正常文字对比度至少 4.5:1；
- 输入框有可关联的 label；
- 图片有描述性 alt；
- 不依赖颜色作为唯一信息；
- 遵守 `prefers-reduced-motion`；
- 页面不能出现横向滚动；
- 内容加载时不能因为数字、标题或按钮出现导致布局跳动。

## 9. 实施顺序

第一阶段只实现凡界核心 UI：

1. 全局导航和修炼状态条；
2. 首页和待办奖励反馈；
3. 修炼总览；
4. 宗门选择；
5. 功法格子和配置；
6. 世界地图和 NPC 关系；
7. 突破试炼和渡劫预览。

第二阶段实现飞升后的 UI：

1. 飞升结算和仙界地图；
2. 仙籍官职；
3. 官署大厅和仙官任务；
4. 仙王、准圣和圣人相关终局界面。

不在第一阶段提前实现仙界空页面，也不因为未来仙官系统改变现有待办、项目和笔记的操作路径。

## 10. UI 验收标准

- 修炼信息可以在首页和待办页被看到，但不遮挡现实任务操作。
- 用户完成任务后可以看到修为、灵石和进度变化。
- 渡劫页面可以解释最终成功率的所有组成部分。
- 宗门、功法、地图和 NPC 页面在桌面与移动端都可以完成核心操作。
- 功法格子、地图节点、概率区块和按钮尺寸稳定，不因异步数据跳动。
- 未解锁内容有明确条件，不显示空白页面。
- 加载、错误、空状态、成功、失败和冷却状态均有明确 UI。
- 使用现有蓝白工作台风格，不引入独立暗黑游戏主题。
- 通过键盘 focus、屏幕阅读器语义、颜色对比度和四种视口检查。

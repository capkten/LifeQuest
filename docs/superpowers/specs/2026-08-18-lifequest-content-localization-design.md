# LifeQuest 内容中文化设计规格

日期：2026-08-18  
分支：`codex/cultivation-progression-ui`

## 目标

将 LifeQuest 中所有系统生成、面向用户展示的内容统一为中文。范围覆盖前端静态文案、数据库中的世界观内容、动态 NPC 与事件、API 展示字段、错误提示、无障碍文本，以及中文替换后的多尺寸 UI 回归检查。

## 范围边界

需要中文化的内容：

- 页面标题、栏目标题、按钮、占位符、Toast、弹窗和空状态。
- `aria-label`、`title` 等用户可感知的辅助文本。
- 境界、资源、宗门类型、功法类型、任务难度和状态的展示名称。
- 数据库中的世界区域、宗门、功法、宗门传承、NPC 描述和系统事件。
- 后端错误、签到记录、奖励日志和金币流水中的系统生成描述。

必须保留的内容：

- `LifeQuest` 品牌名。
- API 路径、数据库字段、内部 key 和稳定事件码。
- 用户自行创建或输入的任务、笔记、项目、商品和描述。
- 已有数据的主键、外键、完成状态、奖励记录和历史关联。

## 当前数据事实

修仙种子数据由 `CultivationService.seed_world()` 创建，包含 9 个世界区域、9 个星级和每星 10 个宗门类型，约 90 个宗门，以及 3 个基础功法。当前部分名称和描述由英文模板生成，例如 `Mortal Domain`、`Cultivation region`、`1-Star Normal Sect`、`Steady Breath` 和 `A disciple of ...`。

启动种子逻辑只在记录不存在时创建数据。因此只修改种子模板无法修复现有数据库，必须增加按稳定 key 执行的幂等回填迁移。

成就、称号和系统财务分类的默认数据大部分已是中文，但签到描述、成就流水、错误信息和历史动态文本仍需要统一审计。

## 设计方案

### 1. 内容目录

新增后端内容目录 `backend/app/services/content_catalog.py`，集中维护：

- 世界区域目录。
- 九星宗门目录和特殊宗门传承。
- 功法名称、描述、类型和境界限制。
- NPC 角色、系统描述和事件模板。
- 境界、宗门类型、任务偏好和资源的展示标签。

新增前端展示字典 `frontend/src/locales/zh-CN.js` 和 `frontend/src/utils/displayLabels.js`，作为 API 缺失展示字段时的 fallback。前端不引入新的国际化依赖，沿用当前 Vue 结构。

稳定 key 只用于逻辑和关联，例如 `qi_refining`、`sect-1-special-7`、`steady-breath`；用户看到的内容来自中文 `name`、`description` 或 `*_label` 字段。

### 2. 数据库种子与回填

种子创建和回填共同使用后端内容目录，避免未来新增内容再次出现英文。

回填按 `node_key`、`sect_key`、`technique_key`、`event_key` 和系统 NPC 角色定位记录。回填只更新可确认属于系统生成的数据，不覆盖用户内容，不修改主键和关系，不删除历史记录，并且重复执行保持幂等。

现有系统记录的中文回填应在启动迁移流程中执行，和已有 SQLAlchemy/SQLite 兼容迁移保持一致。迁移失败必须阻止应用以半完成内容启动，并记录明确日志。

### 3. API 展示字段

保留现有内部字段，同时为可展示枚举提供中文字段，例如：

```json
{
  "realm_key": "foundation",
  "realm_label": "筑基期",
  "kind": "special",
  "kind_label": "特殊宗门",
  "technique_type": "mind",
  "technique_type_label": "心法",
  "task_preference": "discipline-1",
  "task_preference_label": "纪律修行"
}
```

前端优先使用服务器返回的展示字段，只有旧服务器或缺失字段时才使用前端字典。内部 key 不直接渲染到用户界面。

### 4. 错误和动态文本

新增统一的前端 `getErrorMessage(error)`，统一处理 HTTP detail、机器错误码、网络错误和未知错误。所有页面移除直接展示 `response.data.detail` 的分散逻辑。

后端系统生成的签到、奖励、NPC 相遇、修炼日志和金币流水描述使用中文模板。用户输入的自由文本保持原样。机器错误码继续保留稳定值，由前端映射为中文提示。

### 5. 前端页面

按风险分组处理：

1. 修仙页面和共享修仙组件：优先处理境界、资源、功法、宗门、NPC、地图和渡劫。
2. 公共布局、登录注册、首页、待办、资料、项目和商城。
3. 笔记编辑器、笔记工作区、财务、背包、历史和统计页面。
4. 无障碍属性、动态状态、错误状态和 API fallback。

### 6. 中文替换后的 UI 回归

文案替换完成后必须进行独立 UI 检查，不能只依赖静态文案测试。检查 375px、768px、1024px 和 1440px 四个宽度，覆盖首页、待办、修炼、地图、宗门、功法、NPC、渡劫、笔记编辑器、商城、背包、财务和个人资料。

每个页面检查：

- 是否出现水平滚动。
- 中文标题、按钮、标签是否溢出或遮挡。
- 长宗门名、功法名、NPC 描述是否破坏卡片和时间线。
- 弹窗按钮、错误状态和空状态是否保持可用。
- 移动端和桌面端的网格、侧边栏、底部导航是否仍符合当前布局。

发现布局变化时，只调整对应页面的尺寸约束、换行策略、间距和断点样式，不改变业务行为。

## 数据流

```text
content_catalog.py
  -> seed_world / startup backfill
  -> database system content
  -> API key + label response
  -> frontend displayLabels fallback
  -> pages, toasts, dialogs, accessibility text
```

## 验收标准

- 系统生成的修仙世界数据全部为中文。
- 已存在的英文系统数据能够通过幂等迁移回填。
- 用户自定义内容不被修改。
- API 保留稳定 key，同时提供展示 label。
- 前端不直接显示 `qi_refining`、`discipline-1`、`special` 等内部值。
- 常见后端错误、机器错误码和动态奖励文本均显示中文。
- 375px、768px、1024px、1440px 下无水平溢出和明显遮挡。
- 后端全量测试、前端回归测试和生产构建通过。

## 不在本次范围内

- 多语言切换功能。
- 翻译用户自行输入的内容。
- 修改数据库内部 key、API 路径或已有关系。
- 无关的页面重构和视觉风格重做。

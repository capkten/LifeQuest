# 洞府浏览器验收

先启动连接**独立测试数据库**的后端，以及前端开发服务器，再运行：

```bash
npm --prefix frontend run test:browser
```

默认前端地址为 `http://127.0.0.1:3000`，可用 `TEST_BASE_URL` 指向另一个本地测试实例。

需要保留现有前端服务、单独运行新版测试 API 时，可同时设置 `TEST_API_URL`。测试会将页面的 `/api` 请求转发到该真实后端，保留原请求并使用真实响应，不模拟业务数据。例如：

```bash
TEST_BASE_URL=http://127.0.0.1:3001 TEST_API_URL=http://127.0.0.1:8002 npm --prefix frontend run test:browser
```

最终验收优先使用构建后同源应用：先构建前端，再由连接独立测试数据库的后端托管 `frontend/dist`，将 `TEST_BASE_URL` 指向该测试实例，不设置 `TEST_API_URL`。页面刷新会取消旧请求，开发服务的请求转发可能遇到已取消路由；同源验收不需要这层转发。

```bash
TEST_BASE_URL=http://127.0.0.1:8002 npm --prefix frontend run test:browser
```

这些测试使用真实 HTTP API 创建独立测试账号和真实任务，通过浏览器的公开可访问控件验证交互；不会读取组件源码或数据库来断言结果。测试账号会留在测试数据库中，因此不要连接生产或个人日常使用的数据库。

首次成功奇遇用例会真实等待约一分钟；白鹿解锁用例再走三次真实的一分钟目标会话，跨过 80% 阈值后收功。丢失收功响应用例也会真实等待一分钟，服务端结算成功后才丢弃响应，再验证重试不重复发奖。不会修改数据库或为测试新增生产时钟接口，整套浏览器验收需要数分钟。

离线用例在已加载的应用壳中控制 HTTP/浏览器网络边界，验证缓存刷新、待收功持久恢复、跨账号隔离与任务完成置灰；不以模拟业务响应代替服务端结算，也不代表已完成 Android 飞行模式真机验收。原生通知拒绝用例模拟外部 Tauri 通知桥，系统通知点击、锁屏和权限窗口仍需真机验收。

书信资格浏览器用例默认跳过。仅为明确指定的独立审查库启用 `TEST_SEED_DB=D:/codes/LifeQuest/.harness/cave-stage05-runtime/preview.db`；测试先通过 HTTP 注册新的随机账号，再准备该账号的注册日期，以满足来信资格；领奖用例还将这个账号新建的待办创建日期设为四天前，随后通过真实接受、完成任务、领奖接口证明试炼。路径受严格校验，数据库只用于日期前置条件，业务结果仍只通过 HTTP/页面断言，不修改服务器时钟。不要将此变量指向日常使用或生产数据库。

首次引导的常规用例验证键盘写签、真实今日任务、默认 15 分钟、随时跳过和设置中本地重看。旧版洞府空位用例先通过公开 skip API 跳过引导，再断言普通首页；没有改动资格或模拟服务器结果来绕过引导。

完整首次成功流程默认跳过，显式设置 `TEST_LONG_ONBOARDING=1` 后真实等待 15 分钟目标的八成阈值（约 12 分钟），验证凡品、任务完成、引导完成、白鹿仍未解锁和重放不加资源；没有修改会话时间。可单独运行：

```bash
TEST_BASE_URL=http://127.0.0.1:8002 TEST_LONG_ONBOARDING=1 node --test --test-name-pattern="first fifteen-minute retreat" frontend/e2e/cave.test.mjs
```

普通状态和系统边界回归仍使用 `npm --prefix frontend test`；浏览器套件单独运行，不要求普通单元测试先启动服务器。
